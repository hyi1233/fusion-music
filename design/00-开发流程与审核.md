# 00 · 开发流程与审核关卡（G1–G5）

> 本文档定义 Fusion Music 的完整开发流程。**每一关必须通过用户审核才能进入下一关；未通过则修改后重新提交本关，不得跳关。**

## 流程总览

```
G1 需求评审 → G2 策划评审 → G3 UI 设计评审 → G4 功能实现验收 → G5 整体测试验收 → 发布
   01-PRD      02-策划设计      03-UI规格+原型        按定稿UI写功能        动效/滑动/按钮/播放
```

## 关卡定义

### G1 需求评审（本文档：design/01-需求文档-PRD.md）
- **通过标准**：产品定位、两大核心（动态歌词 / 可添加音源）、目标设备、非目标边界，用户逐条确认。
- **不通过处理**：修改 PRD，重新提交 G1。

### G2 策划评审（design/02-策划设计.md）
- **通过标准**：用户故事覆盖"添加音源→切源→浏览该源榜单→播放→看动态歌词"全旅程；功能清单优先级用户认可；参考分析（洛雪/Folia 的对照）被认可。

### G3 UI 设计评审（design/03-UI设计规格.md + design/system/theme.ts + design/prototype/index.html）
- **交付形式**：动态网页原型（单文件 HTML，浏览器直接打开），可交互演示：切源换榜单、遥控器焦点移动、页面滑动/转场、动态歌词示意、添加音源弹窗。
- **通过标准**：用户看过原型并认可所有界面的布局、状态、键位。
- **冻结规则**：**G3 通过之前，冻结 src/ 下一切界面代码**（可复用地基：音源协议层、歌词解析、播放内核、视觉引擎除外）。

### G4 功能实现验收
- **规则**：严格按 G3 定稿的规格与主题实现；每个界面完成后截图实测给用户；实现与设计稿不一致即打回。

### G5 整体测试验收
- **清单**：动效流畅度、窗口/页面滑动、控件按钮（含遥控器方向键/返回键/菜单键）、音乐播放全链路（添加音源→搜索→播放→歌词逐字→切歌→队列）、异常态（音源失效/网络断开）。
- **通过标准**：用户实际使用验收。

## 纪律
1. 评审记录归档于 `design/reviews/`（日期-关卡-结论）。
2. 任何环节的修改必须先改文档再改代码。
3. 每次提交界面相关代码前，必须附设计稿对照截图。
