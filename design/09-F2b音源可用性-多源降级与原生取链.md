## 1. 问题

F2a 之后网页版 UI 已完整可用，但**播放取链只有一条路**：洛雪音源脚本沙箱 → `lxmusicapi.onrender.com`。
本机 IP 被该上游按「禁止批量下载，请规范使用！」拒绝（`code: 1`），于是播放页只能弹红色错误条：

```
播放失败 · 音源服务暂时不可用（可能被限流或封禁 IP）
错误详情：Failed to load because no supported source was found.
```

用户诉求是「播放功能也不能正常工作」。这条链只有一个上游，等于把可用性押在一个会封 IP 的公共接口上。

## 2. 方案

### 2.1 取链顺序（多源降级链）

`resolvePlayUrlWithFallback()` 按固定顺序尝试，每一步都记录**为什么失败**：

| 顺序 | id | 名称 | 说明 |
|---|---|---|---|
| 1 | `direct` | 直链 | `track.url` 已有地址就直接用，不发任何请求 |
| 2 | `custom` | 自定义脚本 | 「设置 → 音源设置」里填的洛雪脚本地址（用户自有源） |
| 3 | `default` | 默认洛雪源 | `lxmusicapi.onrender.com` 内置脚本（走 `/lxapi` 代理） |
| 4 | `native` | 平台原生接口 | 酷我 / QQ / 酷狗各自的原生取链接口（走 `/native/<plat>` 代理） |

任一步成功即返回，并带上 `attempts`（每条尝试的 ok / reason / code）。全失败抛
`ResolveAllFailedError`（`code: 'ALL_SOURCES_FAILED'`），message 里逐条写明每个源失败的原因。

### 2.2 平台原生取链实现

三个平台的原生接口浏览器直连全部被拦（CORS / Origin 校验 / 证书问题），因此实现为
**「页面 → 本地代理 → 上游」**，代理负责补平台要求的 Referer、决定是否发 Origin。

| 平台 | 路径 | 关键参数 |
|---|---|---|
| 酷我 | `antiserver.kuwo.cn/anti/s` | `type=convert_url3&rid=MUSIC_<id>&format=mp3&br=128kmp3` |
| 酷我 | `www.kuwo.cn/api/www/play/url` | `rid=MUSIC_<id>&br=...&format=mp3`（需 csrf + 同源 cookie） |
| QQ | `c.y.qq.com/v8/fcg-bin/fcg_play_single_song.fcg` | `songmid=<mid>&format=json&guid=1000000000` → 取 `media_mid` |
| QQ | `u.y.qq.com/cgi-bin/musicu.fcg`（POST） | `music.vkey/GetVkey` + `music.stream.url/GetUrl` → `purl` 拼 `ws.stream.qqmusic.qq.com` |
| 酷狗 | `mobilecdn.kugou.com/api/v3/song/url` | `hash=&timelength=&format=mp3&bitrate=128&encryptType=0`（http，证书域名不匹配） |
| 酷狗 | `www.kugou.com/yy/index.php?r=play/getdata` | `hash=&album_id=&duration=` |

**踩过的坑（已写进代理规则）**

- 酷我 / QQ / 酷狗**都不能带 `Origin` 头**：酷我返回 `The request is illegal!`，QQ 直接 400，酷狗 `Access Deny !`。代理对这三个平台 `sendOrigin: false`。
- 酷狗 `mobilecdn.kugou.com` 的 https 证书与域名不匹配 → 只能 http。
- 酷我 `www` 取链接口必须走 `www.kuwo.cn`，**不能复用 antiserver 主机**（这是本轮实测发现并修掉的路由 bug）。
- QQ `musicu.fcg` 是 POST，body 通过 `__body=<base64>` 查询参数透传（与歌词中继同一约定）。
- 酷狗取链接口已下线或要求签名，代码里保留实现并明确标注不可用原因。

### 2.3 错误可视化

播放页红色错误条新增「**已尝试的音源**」清单，逐条显示源名与失败原因：

```
已尝试的音源
· 默认洛雪源：无法连接音源服务器，请检查网络
· kuwo 原生接口：酷我原生取链失败（...）
```

设置页新增「取链顺序」说明条，以及「填入本地 mock 音源（调试用）」按钮（一键填入
`${origin}/mock/lx-script.js`），方便在公共源被封时验证自定义源链路。

## 3. 本机实测结论（重要）

公共上游按 IP 封禁是**上游策略**，不是本项目缺陷，但必须如实记录：

| 源 | 本机结果 |
|---|---|
| `lxmusicapi.onrender.com` | `{"code":1,"msg":"禁止批量下载，请规范使用！"}`（按 IP 封禁；换 UA / 加 Referer / 去 key 均无效） |
| 酷我 `antiserver.kuwo.cn` | nginx 403 |
| 酷我 `www.kuwo.cn/api/www/play/url` | `{"success":false,"message":"The request is illegal!"}`（需浏览器指纹 + 同源 cookie） |
| QQ `c.y.qq.com/v8/...` | 200 但 `url` 为空串、`filectrl` 为 null（匿名态拿不到 vkey） |
| QQ `u.y.qq.com/cgi-bin/musicu.fcg` | `{"code":500003,"subcode":860100005}` |
| 酷狗 `mobilecdn.../api/v3/song/url` | `Access Deny ! No Actions !` |
| 酷狗 `www.kugou.com/.../getdata` | `{"data":[],"err_code":20010}` |

因此本机无法靠公共源出声，**但降级链与自定义源链路已验证可跑通**：

- 自定义 mock 音源脚本 → 播放页 `audio.paused === false`，`currentTime` 从 5.80s 前进到 8.80s（**有声音**）。
- 默认链（不带自定义脚本）实测命中了洛雪默认源并成功出声：
  `http://bd-er.kuwo.cn/.../M500004OK6pa2JfRwK.mp3`，`currentTime` 13.8s 持续前进 —— 说明
  `/lxapi` 代理下的默认源在部分歌曲/时段仍可用，被封的只是部分请求。
- 模拟上游全挂时，错误条正确列出每条尝试与原因。

## 6. 遗留

- 本机 IP 被公共源封禁，**公共源的真实可用性无法在本机证明**，只能在未封禁的机器上验证。
- 酷狗取链接口已下线/需签名，当前实现仅保留协议正确的请求与错误说明。
- 若要彻底摆脱上游封禁，需要自建音源代理（不在本任务范围）。
